1. Что такое ИИ-комбайн — общая картина

ИИ-комбайн — это набор локальных сервисов на вашем компьютере, которые вместе дают то, что обычно требует облака: чат с локальными LLM, поиск по личным заметкам (RAG), выполнение команд на машине, работу с Obsidian и автоматическую выкачку статей с Хабра. Ничего не уходит наружу: все сервисы слушают только 127.0.0.1, интернет нужен только для скачивания статей с habr.com.

Главный принцип: Open WebUI — центр. Он единственный, с кем общается браузер; все бэкенды (модели, векторы, инструменты) он вызывает сам, а клиенту отдаёт единый интерфейс чата и API. ZCode и скрипты подключаются так же, как браузер — через :8080 (API) или :8089 (MCP).

Почему нельзя запускать llama-server «вручную из любого терминала»: окружение терминала может нести чужой LD_LIBRARY_PATH (например, из AppImage), и CUDA-бэкенд молча не загрузится — модели будут работать на CPU в 10 раз медленнее. Признак: скорость генерации 3–6 ток/с вместо ~35. Проверка: nvidia-smi должен показывать процесс llama-server.

4. Путь запроса: как работает чат, RAG и инструменты

Когда вы пишете в чат на модели «Obsidian Знания», внутри происходят четыре шага. Понимание этого пути — ключ к диагностике: «модель не видит заметки» почти всегда значит, что сломан один из шагов ниже.

Что важно знать об этом механизме

  • Гибридный поиск = семантика (векторы эмбеддера) + ключевые слова (BM25-ish). Семантика находит «по смыслу» (спросили «железо» — найдётся inxi), ключевые слова — точные вхождения.
  • Источник в ответе — это имя файла из метаданных чанка. Если файл переименовать в vault, надо перезалить его в базу (см. §6).
  • Простые режимы API (без WebSocket) базу автоматически не подключают — передавайте files явно, или используйте полный WS-режим из e2e_knowledge_final.py.
  • Tool-calling — отдельная параллельная способность: модель по описаниям функций (спекам) решает вызвать инструмент, Open WebUI исполняет его и возвращает результат модели. Так работают и Знания (внутренние тулы query_knowledge_files и др.), и весь MCP.

5. llama.cpp и CUDA 13: история пересборки

31.10.2026 pacman обновил CUDA 12 → 13.4, а llama.cpp был собран под CUDA 12 — библиотеки libcudart.so.12 исчезли, и модели молча перешли на CPU (3–6 ток/с вместо 35). Решение — пересборка под CUDA 13 из официального релиза.

Сборка0.5b генерация9B генерация9B обработка промпта
CUDA 12 (старая)63.9 ток/с27.5 ток/с~14 ток/с
CUDA 13 (b12057, прод)308.9 ток/с35.8 ток/с255 ток/с
Vulkan b12057 (запасная, ~/build-llama)91.8 ток/сне тестировалась—
Почему больше не сломается: новая сборка слинкована с системной CUDA 13 (/opt/cuda/lib64), которую pacman обновляет вместе с системой. Обратно совместимость внутри мажорной версии гарантирует soname .so.13. Vulkan-профиль — план Б вообще без CUDA: ему нужен только драйвер.
Ключевые настройки моделей.ini: parallel = 1 — один слот получает весь контекст 32k (авто-режим делит единый KV-пул на 4 слота и даёт «Context size has been exceeded» при двух запросах); ctx-size = 32768 для рабочих моделей; flash-attn on + cache-type-k q8_0 — KV-кэш вдвое меньше.

6. Знания: база заметок Obsidian и синхронизация

База Знаний — это коллекция «База знаний Obsidian» (id dfe4a423-…) в Open WebUI: 62+ markdown-файла из vault, разбитые на чанки и закодированные в векторы. Наполнение — инкрементальное, по хэшам, штатными средствами 0.12.5.

# долить заметки (новые/изменённые/удалённые) — единственная команда:
python3 ~/OpenWebUI-Local/scripts/sync_knowledge.py          # применить
python3 ~/OpenWebUI-Local/scripts/sync_knowledge.py --dry-run # только показать план
Тонкость хэшей: diff сравнивает meta.file_hash — sha256 сырых байтов файла. А колонка file.hash — sha256 извлечённого текста. Поэтому «обновить содержимое» через data/content/update не годится для sync — скрипт перезаливает файл целиком, чтобы хэш совпал.

7. MCP local-tools: 22 инструмента

MCP (Model Context Protocol) — открытый протокол: сервер отдаёт список функций с описаниями, LLM решает, какую вызвать, сервер исполняет и возвращает результат. Включаются в чате меню «+» → «Локальные инструменты». Доступны и из ZCode/скриптов через POST :8089/mcp.

Фильтра по датам на сервере нет — периоды (7/30/90/365 дней) считаются на клиенте по timePublished. «Краткое содержание статьи» кнопкой на Хабре — это ИИ-фича sourcecraft, требующая личного Яндекс-логина, поэтому она не используется: суммари берётся из интро статьи (leadData.textHtml), а при желании составляет локальная модель.

Заметка самодостаточна: один файл, ни внешних ссылок, ни папки с картинками — можно переслать, перенести, и всё отобразится. Проверено: base64 декодируется в валидные PNG (лимиты: 8 МБ на картинку, 40 МБ на заметку, ≤30 картинок).

9. Поиск по локальной базе: «Локал»

kb_search — гибрид двух технологий, поэтому находит и по смыслу, и по точным словам:

РежимКак работаетПример
Семантика (эмбеддер :8082)вопрос → вектор → косинусная близость к векторам конспектов; «TURN сервер для домашней сети» найдёт заметку про WebRTC даже без точных слов0.82 → Slyber TURN Server
Grep со стеммингомкаждое слово → префикс 6 букв («цензура» найдёт «цензуру», «нейросети» → «нейрос»); вес: заголовок ×3, тело ×1находит «HHH-цензуру корпоративных нейросетей»

Итоговый балл = 0.7·семантика + 0.3·grep; каждый результат показывает фрагмент конспекта вокруг первого вхождения и путь к заметке. Тот же поиск доступен модели obsidian-knowledge автоматически (§4) и любому интерфейсу через REST /api/v1/retrieval/query/collection — поэтому база «подключаемая» к чему угодно: чату, ZCode, своим скриптам.

10. Безопасность: гвард, блок-лист, изоляция

  • Токены: секрет сервера — ~/OpenWebUI-Local/.webui_secret_key; JWT для скриптов живёт ≤7 дней (секрет + session_stamp из БД). API-ключ постоянный — создайте в Настройки → Аккаунт.
  • Пароли/ключи нигде не хранятся в конфигах комбайна; на Хабре используются только публичные данные (закладки аккаунта открыты).
