### Схема комбайна (графическая)

Интерактивная схема топологии — **[схема-комбайна.html](схема-комбайна.html)** (лежит рядом, открывается в любом браузере, офлайн).
Там два режима: «Сейчас» (как работает сегодня) и «Целевая схема» (ZCode Desktop + локальная LLM + MCP). Клик по любому узлу — детали, порты и подводные камни.

Кратко, как связаны потоки:

```
Obsidian vault ──(sync знаний, скрипт)──▶ База Знаний Open WebUI (62 файла)
      │                                        │  ▲
      │ (плагин REST API+MCP :27123)           │  │ RAG-поиск (эмбеддер :8082)
      ▼                                        ▼  │
  MCP-инструменты ◀──(tool-calling)── llama-server роутер :8081
      :8089 local-tools                         ▲
                                                │ chat/completions
                                    браузер Open WebUI :8080
```

> **Планируется:** ZCode Desktop подключить к роутеру `http://127.0.0.1:8081/v1` (провайдер OpenAI-совместимый) и к MCP-серверам local-tools (:8089) и Obsidian (:27123) — чтобы агент работал на локальной модели и без лишних запросов наружу. Детали см. в схеме, режим «Целевая схема».

## 3. Знания: поиск по вашим заметкам (главная функция)

### Как пользоваться в браузере
1. Новый чат → вверху выберите модель **«Obsidian Знания (qwen3.5-9b)»**.
2. Задавайте вопрос обычным языком. Модель **сама** ищет по базе: в ответе видно
   статус «Поиск в знаниях» и вызовы инструментов (`query_knowledge_files`,
   `grep_knowledge_files`, `view_file`).
3. Можно явно просить точный поиск: «найди точное вхождение слова X в заметках»
   (модель использует grep).

База: **«База знаний Obsidian»** — 62 заметки из `~/GoogleDrive/Obsidian`
(папки Arch_Linux, ИИ, win, Obsidian; служебная `.obsidian` не индексируется).

### Проверенные примеры запросов
- «Какая команда в Manjaro показывает инфу о железе? Найди в заметках»
  → ответ **`inxi -zv8`** из flashcard «Тренировка памяти.md»
- «Что написано про просмотр логов в Linux?» → находит заметки про journalctl

### Советы по формулировкам
- Поиск **семантический**: формулируйте близко к тексту заметки. Если спросить
  «lshw», а в заметке написано «показывает инфу о железе» — модель может не
  найти с первого раза; переформулируйте словами заметки или попросите grep.
- Вопрос-цитата из заметки (как flashcard) — самый надёжный способ.

### Альтернатива: база вручную
Любой модели можно прикрепить базу/файлы в чате: «+» → «Знания» (или `#`).
Полезно для моделей без tool-calling.

## 4. Инструменты (MCP)

В чате на моделях **qwen3.5-9b / llama-3.1-8b**: меню «+» (инструменты) → включите:
- **Локальные инструменты** (local-tools) — системные скрипты;
- **Obsidian (Local REST API)** — чтение/запись активного vault.

### Поиск: «Хабр» и «Локал» (добавлено 02.11.2026)

Просто напишите в чате (модель с tool-calling сама выберет инструмент):

| Фраза в чате | Что делает | Инструмент |
|---|---|---|
| «Хабр: <любая фраза>» / «найди на habr …» | Поиск по **всему сайту habr.com** по любым словам и темам (не только ИИ): заголовок, автор, теги, описание | `habr_search` |
| «прочитай статью <ссылка habr>» | Полный текст статьи по ссылке (для конспекта/цитаты) | `habr_read` |
| «Локал: <фраза>» / «что в моей базе про …» | Поиск по **локальной базе**: конспекты Habr + заметки vault — ищет и по названию, и по конспекту (семантика через эмбеддер :8082 + grep с учётом падежей) | `kb_search` |

Если ничего не найдено или ошибка — инструмент подсказывает, где искать дальше
(сайт/vault/переформулировать), и модель переспрашивает. Эмбеддер используется
автоматически, когда запущен; без него — grep-режим.

⚠️ Obsidian-MCP работает **только при запущенном приложении Obsidian**
(порт 27123). Плагин работает с **активным** vault
(сейчас `/home/rover/GoogleDrive/Obsidian`, НЕ `/BACK!`).

## 5. Использование через API

### 5.1 Токен
Проще всего — постоянный API-ключ: **Настройки → Аккаунт → API-ключи**
(включить и создать `sk-...`). Использовать как `Authorization: Bearer sk-...`.
Скрипты из `~/OpenWebUI-Local/scripts/` читают JWT из переменной окружения
`WEBUI_JWT` (JWT подписывается секретом из окружения процесса сервера и
живёт ограниченное время — после рестарта сервера выдать новый).

### 5.2 Простой режим (ответ сразу в HTTP, без инструментов)

```bash
curl -s -X POST http://127.0.0.1:8080/api/chat/completions \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{
    "model": "obsidian-knowledge",
    "messages": [{"role":"user","content":"Как посмотреть логи в Linux?"}],
    "stream": false,
    "files": [{"type":"collection","id":"dfe4a423-90f1-4db7-909c-206d599b8f58"}]
  }'
```

⚠️ В простом режиме (без WebSocket) **база из модели автоматически не
подключается** — передавайте её явно через `files` (как выше).

### 5.3 Полный режим (как браузер: Знания + инструменты работают сами)

Все четыре условия **обязательны** (иначе ответ «теряется»):
1. WebSocket-подключение с токеном: `socketio_path="/ws/socket.io"`,
   `auth={"token": ...}`, транспорт `websocket` (polling на сервере отключён);
2. `session_id` = **Socket.IO sid** этого соединения (`sio.get_sid()`), а не
   случайный UUID;
3. В теле запроса поле **`"id"`** — uuid assistant-сообщения;
4. **`"stream": true`** — нативные инструменты работают только на
   streaming-пути.

Ответ приходит **не в HTTP** (там только `{"status":true,"task_ids":[...]}`),
а событиями WebSocket: событие `events`, формат
`{"chat_id":..., "message_id":..., "data":{"type":"chat:completion", ...}}`.

Готовый образец клиента: `~/OpenWebUI-Local/scripts/e2e_knowledge_final.py`.

### 5.4 Прямой поиск по базе (без модели)

```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/retrieval/query/collection \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"collection_names":["dfe4a423-90f1-4db7-909c-206d599b8f58"],
       "query":"как посмотреть логи","k":3}'
```
Ответ: `documents` (тексты чанков), `metadatas` (источник = имя файла).

## 6. Обслуживание

### Добавление новых заметок в базу
- **Основной способ (инкрементально, без дублей)**:
  `python3 ~/OpenWebUI-Local/scripts/sync_knowledge.py`
  Сравнивает sha256 vault-файлов с базой через штатный `sync/diff` 0.12.5:
  новые — добавляет, изменённые — перезаливает со сменой версии, удалённые
  из vault — убирает из базы. Повторный запуск на неизменённой базе ничего
  не делает. Сначала посмотрите план: `--dry-run`.
  Опции: `--dry-run` (только показать diff), `--mode structured`
  (зеркалить папки vault директориями в базе; по умолчанию auto — сейчас
  база плоская и режим определяется как flat), `--keep-remote`
  (не удалять из базы то, чего нет в vault).
- Первичная загрузка (только когда база пуста!):
  `python3 ~/OpenWebUI-Local/scripts/load_knowledge.py` — повторный запуск
  даёт безвредные ошибки «Duplicate content detected»; вместо этого
  используйте sync-скрипт.
- Ручной путь: **Рабочее пространство → Знания → База знаний Obsidian → «+»**.
- Токен для скриптов: JWT в `/tmp/webui_jwt.txt` (умирает после рестарта
  сервера — см. п. 5.1; секрет сервера живёт в `~/OpenWebUI-Local/.webui_secret_key`,
  в environ процесса его нет — CLI подставляет его из файла).

curl http://127.0.0.1:8080/api/version       # 0.12.5

```bash
DB=~/OpenWebUI-Local/.venv/lib/python3.11/site-packages/open_webui/data/webui.db
sqlite3 "$DB" ".backup '${DB}.bak-$(date +%Y%m%d)'"
```
Существующие бэкапы: `webui.db.bak-20261024`, `webui.db.bak-20261031`,
`webui.db.bak-20261031-pre-0.12.5`.

### Порядок старта после перезагрузки
1. llama-server (роутер :8081), эмбеддер (:8082), local-tools (:8089) —
   вашим скриптом `~/AiStart/start_ai.sh` (он сам подключает CUDA 12-библиотеки
   из `.venv-cuda12` — после обновления CUDA до 13.x это обязательно, иначе
   модели молча работают на CPU);
2. Open WebUI: `cd ~/OpenWebUI-Local && .venv/bin/open-webui serve --host 127.0.0.1 --port 8080`;
3. Obsidian — если нужен MCP Obsidian.

⚠️ Не запускайте роутер/серверы вручную из терминала с чужим окружением
(например, из запущенного ZCode) — используйте `start_ai.sh`: он ставит
правильный `LD_LIBRARY_PATH`. Признак CPU-фолбэка: скорость генерации
~3–6 t/s вместо ~27 t/s и `nvidia-smi` без процесса llama-server.

### Рестарт Open WebUI (сохранение секрет для API-токенов)
```bash
# 1) запомнить секрет ТЕКУЩЕГО процесса (иначе старые токены умрут):
SECRET=$(tr '\0' '\n' < /proc/$(pgrep -f 'open-webui serve' | head -1)/environ \
         | grep '^WEBUI_SECRET_KEY=' | cut -d= -f2-)
# 2) остановить (НЕ pkill -f — убьёт собственную оболочку!):
kill $(pgrep -f 'open-webui serve')
# 3) запустить:
cd ~/OpenWebUI-Local && WEBUI_SECRET_KEY="$SECRET" nohup \
  .venv/bin/open-webui serve --host 127.0.0.1 --port 8080 > /tmp/openwebui.log 2>&1 &
```
Если рестарт сделали без секрета — ничего страшного: в браузере просто
перелогиньтесь, скриптам выдайте новый токен.

## 7. Известные грабли и решения

| Симптом | Причина | Решение |
|---|---|---|
| Модели пропали после правки соединений | `openai.enable` стал `null` | `UPDATE config SET value='true' WHERE key='openai.enable';` и рестарт |
| Obsidian-инструменты молчат | Приложение Obsidian не запущено | Запустить Obsidian (порт 27123) |
| Модель «не видит» заметки через API | Нет `session_id`/`id` или `stream=false` | Полный режим (п. 5.3) или явные `files` (п. 5.2) |
| RAG молча не ищет | Выключена генерация retrieval-запросов | Админ → Настройки → Интерфейс: включить «генерацию поисковых запросов» (`task.query.retrieval.enable=true`) |
| Инструменты Знаний возвращают пусто | В модели тип базы `knowledge` вместо `collection` | Редактор модели: knowledge item type = `collection` |
| Модель игнорирует инструменты | Модель без tool-calling (qwen2.5-coder) | Взять qwen3.5-9b / llama-3.1-8b |
| MCP initialize отвечает 406 | Нет специальных Accept-заголовков | `Accept: application/json, text/event-stream` |
| Векторная БД «пустая» на вид | Chroma 2.x хранит данные в HNSW `.bin`-файлах, не в sqlite | Это норма; проверять поиском через API (п. 5.4) |
| HTTP 401 «Invalid token» у скриптов | Секрет сервера сменился после рестарта | Выдать новый JWT/ключ (п. 5.1, 6) |
| Модели работают на CPU (~3-6 t/s) | CUDA 13 несовместима с llama.cpp (сборка под CUDA 12) | Запускать через `start_ai.sh` (он подключает CUDA 12 из `.venv-cuda12`); секция «Порядок старта» |
| «Context size has been exceeded» при 2+ запросах | Роутер делил единый KV-пул на 4 слота (`parallel=auto`) | `parallel = 1` в `models.ini` (секция `[*]`), рестарт роутера |
| События чата через API приходят пустыми | Текст идёт в `response:completion` (reasoning/output_text delta), не в `chat:completion` | Собирать дельты `response.reasoning_text.delta` и `response.output_text.delta` (см. e2e_habr_kb_tools.py) |

## 9. Краткая шпаргалка «как задать вопрос по заметкам»

1. Открыть http://127.0.0.1:8080 → новый чат.
2. Модель: **Obsidian Знания (qwen3.5-9b)**.
3. Спросить: «Что в моих заметках про …?» / «Найди в заметках …».
4. При необходимости уточнить: «открой файл … и процитируй», «найди точное
   вхождение …».
5. Ответ придёт с указанием заметок-источников; можно переспросить detail
   по конкретному файлу.
