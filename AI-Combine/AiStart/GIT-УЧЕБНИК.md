# Git — учебник для работы с этим репозиторием

Короткий практичный курс: только то, что нужно для ежедневной работы
с репозиторием `ai-combine`. Все команды выполняются из любого каталога —
репозиторий в корне домашней папки, git сам найдёт его (или добавляйте `-C /home/rover`).

## 1. Что такое Git — за 60 секунд

- **Репозиторий** (`.git/` в `/home/rover`) — архив всех версий всех файлов проекта.
- **Коммит** — «снимок» файлов + подпись кто/когда/зачем. У каждого коммита — уникальный хэш (например `a1b2c3d`).
- **Ветка** — линия истории. У нас одна рабочая: `main`.
- **Remote** — внешнее хранилище того же репозитория. У нас два: `back` (диск BACK) и `github`.
- **push** — отправить свои коммиты в remote. **pull** — забрать оттуда. **clone** — склонировать заново.
- **Рабочая зона → индекс → коммит**: сначала вы меняете файлы, потом `git add` выбирает что войдёт, потом `git commit` фиксирует.

## 2. Ежедневный цикл (учите эти 4 команды)

```bash
git status                 # что изменилось? (самая частая команда)
git add -A                 # взять всё изменённое в будущий коммит
git commit -m "feat: что сделал"   # зафиксировать снимок
git push back main         # отправить на диск BACK
git push github main       # отправить на GitHub
```

**Правило хорошего сообщения коммита:** `тип: что сделано` —
`feat:` новая возможность, `fix:` исправление, `docs:` документация,
`chore:` обслуживание, `refactor:` переработка без изменения поведения.

## 3. Посмотреть историю и изменения

```bash
git log --oneline --graph -15   # последние коммиты одной строкой
git show                        # что в последнем коммите
git diff                        # что изменено, но ещё НЕ закоммичено
git show a1b2c3d:AiStart/mcp_server.py   # посмотреть файл на любой момент истории
```

## 4. Откат — три ситуации

```bash
# а) испортил файл, не закоммитил — вернуть к последнему коммиту:
git restore AiStart/mcp_server.py

# б) закоммитил, но не отправил — отменить ПОСЛЕДНИЙ коммит, файлы оставить:
git reset --soft HEAD~1

# в) вернуть конкретный файл к версии из старого коммита:
git restore --source=a1b2c3d AiStart/models.ini
```

Всё, что попало хотя бы в один коммит, **никогда не теряется** —
историю можно просмотреть в любой момент (`git log`).

## 5. Хранилища (remotes)

```bash
git remote -v               # список: back, github
git push back main          # резервная копия на BACK
git push github main        # облако GitHub
git clone /run/media/rover/BACK/git/ai-combine.git ~/restore-test  # восстановиться целиком
```

**Если диск BACK не смонтирован** — push на `back` выдаст ошибку «not a git repository»:
просто смонтируйте диск и повторите. GitHub работает всегда, где есть интернет.

## 6. Чего НЕ делать

1. **Не редактируйте `.gitignore` без нужды** — это белый список проекта; убрав строку,
   рискуете закоммитить секрет (проверка перед push: `git ls-files | grep -iE 'key|token|secret'`
   — вывод должен быть пустым).
2. **Не делайте `git add .` вне репозитория-корня** — мы всегда `git add -A` из `/home/rover`.
3. **Не правьте историю после push** (`rebase -i`, `reset --hard` на запушенное) — пока учитесь, не нужно.
4. **Не храните в репозитории секреты** — пароли и токены только в файлах вне белого списка.

## 7. Шпаргалка «если что-то пошло не так»

| Ситуация | Команда |
|---|---|
| Хочу увидеть, что войдёт в коммит | `git status` + `git diff --staged` |
| Случайно добавил лишний файл | `git restore --staged <файл>` |
| Хочу вернуться к «как было вчера» | `git log --oneline` → `git restore --source=<хэш> <файл>` |
| Push на BACK ругается | Смонтируйте BACK: `ls /run/media/rover/BACK` |
| Забыл, что означают команды | `git help <команда>` или этот файл |
